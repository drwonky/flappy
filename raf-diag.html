How to read this

 
    
  
  • vsync Hz: the display refresh as the page sees it, the median of the last 15 rAF timestamp intervals (the same idea the game's pacer uses). Later modes reuse the Idle figure (or ?hz= if given) so a mode that is itself slow cannot hide its own misses.
    • 
  
  • interval: gap between consecutive rAF timestamps (ts, the frame's vsync time in Chromium). k = interval / vsync, rounded: 1 is on time, 2 or more means whole refreshes were skipped. Skipped ts = frames dropped (or rAF paced slower) upstream of your code.
    • 
  
  • latency: performance.now() at callback start minus ts. Regular ts with big or irregular latency = the main thread (OS or browser) ran the callback late.
    • 
  
  • heartbeat: a MessageChannel loop independent of rendering. A "stall" is a gap over 16 ms between its own callbacks: the event loop was not running. Stalls that coincide with skipped frames (same time axis in the graph) mean the main thread itself was starved.
    • 
  
  • long tasks: tasks over 50 ms reported by the browser (if supported).
    • 
  
  • work: how long the page's own callback took. If work is short but frames are skipped, the loss is after JavaScript: compositor, raster, GPU or OS.
    • 
  
  • Modes: Idle is the baseline. CPU 4 / 10 ms add main-thread load (10 ms must miss at 120 Hz, not at 60). Canvas 2D and WebGL load raster and GPU fill at full device resolution. Timer-driven uses setTimeout(16) for comparison.
    • 
  
  • Remote: Enter/OK restarts everything; Left/Right runs one mode. Options in the URL: ?secs=20 seconds per mode, ?hz=120 the display's real rate, ?graph=0 no graph during Idle, ?graph=none never draw it while running, ?hb=spin heartbeat by message hops only.
